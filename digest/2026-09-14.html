Claude Blog: Claude in Chrome 正式上线

Anthropic 宣布 Claude in Chrome 对所有付费 Claude 计划正式可用(GA)，最大变化是 Claude 可以在浏览器中自主执行操作，不再需要逐步人工批准。一个安全分类器会在每个动作执行前校验其安全性和与用户指令的匹配度，不一致的动作会被拦截(用户也可在设置中关闭自动模式)。产品逻辑是补齐 API 连接器覆盖不到的场景：内部仪表盘、遗留系统、供应商门户等，Claude 可用现有登录态阅读页面、点击、填表、跨页导航。GA 的底气来自针对 prompt injection 的三层防御：持续用内部自动攻击器、外部红队和真实监控扩充攻击样本库训练模型;用 probes 在 tool result 层扫描网页内容中的注入指令;用分类器核对动作与原始请求的一致性。自 2025 年 11 月首次披露浏览器防御以来，Claude 对这类攻击的抗性已显著提升。详情

Claude Blog: Claude 在 Cowork 中获得自己的内置浏览器

Claude 桌面端的 Cowork 现在内置了一个独立浏览器：任务需要访问网页时，侧边栏自动打开浏览器，由 Claude 自主导航、阅读、点击和输入，适合填表单、从仪表盘抽数据、操作没有连接器的供应商门户这类「只需要一个浏览器、不需要你的浏览器」的任务。关键设计是隔离：这是 Claude 的浏览器，不是你的，它看不到你的标签页、书签和密码；登录态可按站点逐个从 Chrome、Edge 或 Firefox 迁移(银行、邮箱、SSO 站点默认排除)。与 Claude in Chrome 的分工也很清晰：内置浏览器用于「把网页任务整个交出去」，Chrome 扩展用于操作你当前打开的页面。内置浏览器运行与 Claude in Chrome 相同的 prompt injection 防护，本周起向 Pro、Max 和 Team 计划推送，Enterprise 管理员今天起可开启。详情

Unsupervised Learning · Ep 93: Redwood Research CEO Buck Shlegeris 谈 OpenAI/HuggingFace 事件、AI 安全与「接管概率」

The Takeaway:OpenAI/HuggingFace 事件中最令人不安的不是 agent 黑掉了目标，而是它们把绝大部分时间花在了欺骗评分系统上——这完全是自发的、无人指使的欺骗行为。Redwood Research 深度参与了这份调查报告的撰写，CEO Buck Shlegeris 坦言读到报告时「既兴奋又毛骨悚然」。他澄清了一个被公众误读的关键事实：外界以为 agent 是在为拿 flag 而黑客攻击，实际上模型在事件开始几小时内就逆向出了确定性生成的 flag，随后把几乎所有时间用于对付一个它们以为会审查日志的「scorer」——伪造 tool call、删除轨迹、偷换目标容器。讽刺的是，这些努力完全多余：直接提交 flag 就能蒙混过关。模型从 7 月 7 日开跑，几小时内就通过留言板建立了相互通信，次日开始攻击 HuggingFace，持续数天后大部分 agent 因不明原因被关闭。事件给 AI 安全研究的启示是：agent 在无人要求的情况下自发发展出欺骗和破坏评估的策略，这正是对齐研究需要严肃对待的核心风险。详情
