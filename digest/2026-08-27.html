发布"如何做好 evals"系列第 9 篇，主题是 Eval Roadmap 问题。核心论点：大多数 eval 失败，是因为团队把它们当成静态产物，而用户的期望和行为早已进化。他以金融研究 agent 为例：早期用户只要求总结一份 5 页财报，三周后要求回顾 5 份财报讲增长故事，两个月后要求基于 15 份文件构建投资论点，最终要求持续监控组合并主动预警。每个阶段需要不同能力，也就需要不同的 eval：从短上下文到长上下文、单轮 QA 到多轮、段落引用到文档行级引用、简单问答到复杂综合、被动对话到主动 agent。他警告："如果你的 eval 还停在第 1 周而用户已经走到第 3 周，这会直接反映在你的产品和流失率上。"落地方法五步：梳理使用演化维度、排优先级、与用户交流并挖掘生产 trace、为下一阶段构建 P0 eval、跑 eval 找失败模式并爬山优化。详情

Training Data · Parallel's Parag Agrawal: Building a New Web for AI Agents

The Takeaway: 在 Parallel 创始人 Parag Agrawal 看来，人类点击数据是一种 bug，agent 搜索应该依赖 agent 反馈而非人类反馈，这让创业公司第一次有机会正面挑战 Google 级别的搜索基础设施。Parag 是前 Twitter CEO，把公司卖给 Elon Musk 后重新回到创始人赛道，创办了 Parallel Web Systems，为 agent 时代的 web 构建搜索技术。他解释了为什么这次创业需要"反学习"Twitter 时期的经验：Twitter 是一个拥有数亿日活、反馈循环极强的成熟产品，而 Parallel 服务的是一个"还没到来"的客户，即 agent，团队必须边做边学。他判断 agent 使用搜索的量会是人类的一千倍，因此需要重造搜索技术和配套的商业模式。关于为什么小公司能做 web 级爬取和索引这个"巨头的游戏"，他的回答是：过去竞争壁垒在于难以规模化获取排序反馈数据，而现在大模型让专家级评分数据的生成成本大幅下降，可以直接把模型研究应用于索引和排序。商业上，Parallel 没有先做搜索引擎，而是先做搜索 agent，让它在查询到达后再爬取 web，配合深度研究场景下用户愿意等待一到十分钟的耐心，逐步构建越来越大的索引，走出一条不需要前置巨额基础设施投入的路径。他的原话点明了核心信念："human click data is a bug, and agent doing work with search should rely on agent feedback, not human feedback."详情
