### Anthropic Engineering: Scaling Managed Agents: Decoupling the brain from the hands
这篇讲 Claude 平台新服务 **Managed Agents** 的架构演进，核心思路是"harness 里编码的假设会随模型进步而过时"。例如 Sonnet 4.5 有"context anxiety"（快到上下文上限就草草收工），为此加了 context resets，但同一 harness 跑 Opus 4.5 时该行为已消失，reset 成了死代码。他们借鉴操作系统把硬件虚拟成 process、file 等长寿抽象的思路，把 agent 虚拟化为三个可独立替换的接口：session（append-only 日志）、harness（调用 Claude 并路由工具的循环）、sandbox（执行环境）。第一版把所有组件塞进一个容器，变成了基础设施里说的"pet"（不可替代的宠物），容器一挂 session 就丢，且因为容器里有用户数据，工程师连进去 debug 都做不到。最终方案是把**"大脑"（Claude + harness）与"双手"（sandbox 和工具）解耦**，各自独立失效和替换。[详情](https://www.anthropic.com/engineering/managed-agents)

### Claude Blog: Claude Code now supports artifacts
Claude Code 新增 **artifacts** 功能：session 的工作过程可以被捕捉成实时更新的可分享网页，包括 PR 讲解、系统说明、dashboard 和 release checklist。关键在于它直接利用 session 的全部上下文构建，不需要接数据源或搭基础设施。一个 incident 页面可以把代码里失败的测试、监控工具的错误曲线和 session 里的根因推理聚合到一页，页面会在 Claude 更新时原地刷新，每次发布是同一链接下的新版本，带版本历史。默认仅作者可见，只能分享给组织内经认证的成员，不能公开，管理员可用 org 级开关和合规 API 管控。内部测试中最高频场景是**调试**：工程师晨会前发起 incident 调查，Claude 发布包含时间线、可疑 commit 和错误率图表的 artifact，晨会开始前已随调查进展自动更新两次，团队看到的是同一个视图。[详情](https://claude.com/blog/artifacts-in-claude-code)
