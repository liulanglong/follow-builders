### Claude Blog: Claude in Chrome 正式可用
Anthropic 宣布 Claude in Chrome 在所有付费计划上 GA，并且 Claude 现在可以在浏览器中**自主执行操作**，不再需要每一步都人工批准。每次操作执行前会有一个安全分类器验证其安全性和与用户请求的匹配度，不匹配则直接拦截。文章重点阐述了针对 **prompt injection** 的三层防御：一是用内部自动化攻击器、外部红队和真实世界监控构建的攻击库持续训练模型，自 2025 年 11 月以来 Claude 对此类攻击的抵抗力大幅提升；二是 probes 在 Claude 行动前扫描网页内容，检测到疑似攻击时提醒 Claude 保持怀疑并在必要时向用户确认；三是操作前分类器审核，机制与 Claude Code 的 auto mode 相同，用户也可在设置中关闭。对用户而言，这意味着 Claude 现在可以访问内部仪表盘、遗留系统和供应商门户这些没有 connector 的工具，用现有登录态读页、点击、填表。[详情](https://claude.com/blog/claude-in-chrome-generally-available)

### Claude Blog: Claude 在 Cowork 中获得自己的浏览器
Claude 桌面端的 Cowork 现在内置了一个浏览器：任务需要用网站时，侧边栏自动打开，Claude 自己导航、阅读、点击、输入。用户可以把任务的网页部分整个交给 Claude，比如填表单、从仪表盘抽数据、操作没有 connector 的供应商门户，无需扩展、无需配置。关键设计是“这是 Claude 的浏览器，不是你的”：Claude 看不到你的标签页、书签和密码，登录态可以按站点从 Chrome、Edge、Firefox 逐个迁移，银行、邮箱和 SSO 站点默认排除。产品定位上，内置浏览器适合把网页任务整体交出去(如收集发票、做调研)，而 Claude in Chrome 适合操作你已打开的页面和已登录的账号(如更新 CRM、处理收件箱)，两者可在 Settings → Cowork → Preferred browser 中切换。该功能一周内推送到 **Pro、Max 和 Team 计划**，Enterprise 管理员今天起可为组织开启，并沿用与 Claude in Chrome 相同的 **prompt injection 防护**。[详情](https://claude.com/blog/cowork-built-in-browser)
