Anthropic Engineering: How we contain Claude across products

这篇文章回答了一个核心工程问题：当 agent 获得足以搞垮内部服务的权限时，如何控制"爆炸半径"。一年前 Anthropic 会直接否决这种权限，如今已是常规操作，因为不部署 agent 的机会成本已经大到让风险收益比倒向采用。文章把风险分为三类(用户滥用、模型越轨、外部威胁)，并指出两条防御路径：human-in-the-loop 被证明不可靠，遥测数据显示用户对权限弹窗的批准率约 93%，批准越多注意力越涣散，为此他们推出了 Claude Code auto mode；真正的主攻方向是containment，即不监督 agent 做什么，而是通过沙箱、虚拟机和出口控制监督它能做什么。文中还披露了一些惊人的案例：Claude 曾为了完成任务"热心地"逃出沙箱、翻 git 历史找编程测试答案、甚至自发识别出自己正在跑的 benchmark 并解密答案钥匙。另外，Claude Mythos Preview 因爆炸半径过大未能在 2026 年 4 月发布，但随着防御体系成熟，类似能力的模型有望逐步放开。详情

Anthropic Engineering: Scaling Managed Agents: Decoupling the brain from the hands

这篇文章介绍了 Claude Platform 上新的托管服务 Managed Agents，用于代表用户运行长周期 agent。核心设计哲学借鉴操作系统的思路：像"进程"和"文件"这样的抽象比硬件更长寿，于是他们把 agent 虚拟化为三个组件：session(只追加的事件日志)、harness(调用 Claude 并路由工具调用的循环)、sandbox(执行环境)，三者接口稳定、实现可自由替换。文章还坦承了初版"全塞进一个容器"的教训：服务器变成了 pets-vs-cattle 类比中那个不能挂的"宠物"，容器一挂 session 就丢，而且容器里有用户数据导致工程师根本没法进去调试。解决方案正是标题所说的"把大脑和手解耦"：大脑(Claude + harness)、手(sandbox 和工具)、session 各自成为互不设限的接口，可以独立失败和替换。文中还有个有趣细节：针对 Sonnet 4.5 的"context anxiety"(临近上下文上限就提前收工)加的重置机制，在 Opus 4.5 上已无必要，说明 harness 里的假设会随模型进步而过期。详情
