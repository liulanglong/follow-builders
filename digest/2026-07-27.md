### Anthropic Engineering: An update on recent Claude Code quality reports

针对近期用户反馈 Claude 响应质量下降的问题，Anthropic 进行了详细的事后复盘，确认问题源于三个独立的变更，且完全没有影响到 API 层。这三个 bug 分别是：为了降低 UI 卡顿延迟，将 Claude Code 的默认 **reasoning effort** 从 high 降到了 medium，但这被证明是错误的权衡；其次是一个清理闲置会话上下文的 bug，导致模型在后续对话中每轮都在遗忘，显得十分健忘；最后是减少冗长输出的 system prompt 指令意外损害了编码质量。Anthropic 坦言，因为这些变更分别在不同时间表上影响了不同的流量切片，导致整体看起来像是大范围的不稳定。目前所有问题已在 v2.1.116 中修复，并为所有订阅用户重置了使用额度限制。[详情](https://www.anthropic.com/engineering/april-23-postmortem)

### Anthropic Engineering: Scaling Managed Agents: Decoupling the brain from the hands

Anthropic 详细阐述了 **Managed Agents** 的架构设计哲学：将 agent 的"大脑"（Claude 及其 harness 循环）与"双手"（执行代码和操作文件的 sandbox）以及"会话"（事件日志）彻底解耦。文章指出，早期将所有组件塞进单个容器的做法，让服务器变成了难以维护的"宠物"（pet），一旦无响应不仅会丢失会话，还因为涉及用户数据而极难调试。通过借鉴操作系统将硬件虚拟化为"进程"和"文件"的思路，Anthropic 为 agent 建立了高度抽象的接口。这意味着底层实现可以自由替换，同时客户也能轻松地将 agent 连接到自己的私有云或 VPC 环境中，彻底解决了基础设施耦合的痛点。[详情](https://www.anthropic.com/engineering/managed-agents)

### Claude Blog: New in Claude Managed Agents: self-hosted sandboxes and MCP tunnels

Claude Managed Agents 推出了两项重磅更新：支持 **self-hosted sandboxes**（自托管沙箱）和 MCP tunnels（MCP 隧道）。自托管沙箱允许 agent 在企业完全控制的基础设施内执行工具，确保敏感文件、代码库和数据绝不离开企业安全边界，同时支持 Cloudflare、Daytona、Modal 和 Vercel 等主流托管提供商。而 MCP 隧道则提供了一种极其安全的方式，让 agent 能够连接到企业内部私有网络中的 MCP 服务器，调用内部数据库或私有 API，且无需向公网开放任何入站端口。这意味着高安全要求的企业现在可以放心地让大模型 agent 在内部运转。[详情](https://claude.com/blog/claude-managed-agents-updates)
