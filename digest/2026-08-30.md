### Anthropic Engineering: 关于近期 Claude Code 质量报告的更新
Anthropic 公开复盘了用户反馈「Claude 变笨了」的根因：三个独立变更叠加造成了看似随机的质量下降，**API 层从未受影响**。三个问题分别是：3 月 4 日把 Claude Code 默认推理强度从 high 降到 medium（官方承认这是错误的取舍，4 月 7 日回滚）；3 月 26 日的会话清理逻辑出现 bug，导致闲置会话每轮都被清除旧 thinking，让 Claude 显得健忘和重复（4 月 10 日修复）；4 月 16 日为减少啰嗦而加的 system prompt 指令与其他改动叠加损害了编码质量（4 月 20 日回滚）。全部问题已在 **v2.1.116** 中解决，并宣布为所有订阅者**重置用量额度**。文章坦承这些变化分散在不同流量切片上，初期连内部 evals 都无法复现问题。这篇 postmortem 是研究「模型没变但产品体验变差」这一现象的绝佳案例。[详情](https://www.anthropic.com/engineering/april-23-postmortem)

### Anthropic Engineering: Scaling Managed Agents: 把大脑和双手解耦
Anthropic 推出了 **Managed Agents**：一个在 Claude 平台上托管运行长周期 agent 的服务。核心设计哲学借鉴操作系统：像 process 和 file 这样的抽象比任何具体硬件都活得久，所以他们把 agent 虚拟化为三个可独立替换的接口：**session（只追加的事件日志）、harness（调用 Claude 并路由工具的循环）、sandbox（执行环境）**。文章坦承第一版把所有组件塞进单个容器，结果养出了「宠物」而非「牲畜」：容器挂了 session 就丢了，而且因为容器里有用户数据，工程师甚至没法开 shell 调试。最终方案是把「大脑」（Claude 和 harness）与「双手」（sandbox 和工具）解耦。文中还有一个精彩观察：harness 里编码的假设会随模型进步而过时，比如 Sonnet 4.5 的「context anxiety」在 Opus 4.5 上已消失，针对它加的 context reset 成了死代码。[详情](https://www.anthropic.com/engineering/managed-agents)
