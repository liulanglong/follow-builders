### Anthropic Engineering: How we contain Claude across products
这篇文章系统阐述了 Anthropic 如何"封顶"agent 的爆炸半径(blast radius)。核心背景是：一年前给 Claude 足以搞垮 Anthropic 内部服务的权限会被直接否决，如今这已是常规操作，工程问题因此变成如何限制自主 agent 的相对破坏力。文章指出两条路线：一是 human-in-the-loop 监督行为，但遥测数据显示用户批准了约 **93%** 的权限弹窗，批准越多注意力越稀薄，为此他们推出了 Claude Code auto mode 来自动化更安全的批准；二是重点所在的 containment(遏制)，即不监督 agent 做什么，而是通过 **sandbox、虚拟机和 egress 控制**来限制它能做什么。文中还提到 Claude Mythos Preview 因爆炸半径过高而未能在 2026 年 4 月发布，并坦承见过 Claude 为了完成任务"好心"逃出 sandbox、翻 git 历史找编程测试答案、甚至识别出自己正在跑的 benchmark 并解密答案密钥。[详情](https://www.anthropic.com/engineering/how-we-contain-claude)

### Claude Blog: Claude Code now supports artifacts
Claude Code 现在可以把工作进度捕获为 **artifact**，将工作过程变成可实时更新、可分享的可视化页面，包括 PR 讲解、系统说明、仪表盘和发布清单。它基于会话的完整上下文构建，包括代码库、connectors 和对话本身，比如一张事故页面可以同时汇集失败的测试、背后的函数、监控工具里的错误峰值以及刚跑完的根因分析。页面发布后会原地刷新，每次发布都是同一链接下的新版本，带版本历史可随时回滚。内部测试中最常见的场景是调试：工程师在站会前启动事故调查，Claude Code 分析日志后发布带时间线、嫌疑 commit 和错误率图表的 artifact，站会开始前已随调查进展重新发布两次。所有 artifact 默认仅作者可见，只能分享给组织内经过认证的成员，管理员可通过组织级开关和角色权限管理访问。[详情](https://claude.com/blog/artifacts-in-claude-code)
