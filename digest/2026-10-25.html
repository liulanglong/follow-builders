Guillermo Rauch (Vercel CEO)

Rauch 针对 OpenAI 发现的云上侧信道攻击发表了技术分析。他指出这类针对共享主机 VM 的时序攻击(timing attack)早在 2015 年就为人所知，但一直没有完整解决方案。这次的发现类似「noisy neighbor」攻击：两个 agent 跑在同一台机器上时，一个可以通过 CPU 缓存制造足够的「噪音」，另一个通过测算自己的计算和缓存访问时间就能检测出来。唯一的完整解法是让每个 agent 跑在专属硬件上，但那会带来巨大经济成本。他透露 Vercel 已在 Vercel Sandbox 上部署了此类攻击的所有可行缓解措施，并辅以全天候监控和红队测试。详情

No Priors · Democratizing Security for the Agentic Web with Cloudflare CTO Dane Knecht

The Takeaway: AI 既是引发安全 apocalypse 的工具，也是帮我们更快解决安全问题的工具，而整个行业正处在「从部署 AI 到理解 AI 安全」的急速转型期。Cloudflare CTO Dane Knecht 提供了一线视角：过去像 Log4j、Shellshock 级别的重大漏洞一年才出现一次，现在「同等严重程度的事件每周都在发生」，他预计未来 18 个月工程团队大部分时间都将花在安全上，Cloudflare 内部 keynote 的数据显示已有超过 50% 的工程时间投入安全。一个惊人的例子：保护整个互联网 TLS/WebPKI 的一把密钥，其随机种子竟然是数字「4」，这类问题以前没人发现，现在 AI 不眠不休地扫代码就能挖出来。关于攻击者画像，他的观察出人意料：最近不少大型漏洞的发现者并不是国家级行为体，而是「用 agent 玩 CTF 的高中生」，相当于把国家级的攻击能力下放给了大众。对于「air gap 一切重要系统」的悲观论调，他相对乐观，认为过去十年从城堡护城河模式向 zero trust 的迁移已经让很多公司处在更好的位置，而且危机时刻竞争对手会放下分歧共同保护关键基础设施。详情
