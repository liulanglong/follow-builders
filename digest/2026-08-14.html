Anthropic Engineering: An update on recent Claude Code quality reports

Anthropic 公布了近期 Claude Code 质量下降问题的详细调查结果，确认 API 层从未受到影响，所有问题已在 4 月 20 日（v2.1.116）全部修复。调查发现三个独立问题：第一，3 月 4 日将默认 reasoning effort 从 high 降到 medium 以减少延迟，导致用户感觉模型变笨，4 月 7 日已回滚；第二，3 月 26 日上线了清理空闲会话旧 thinking 的功能以降低恢复延迟，但 bug 导致每轮对话都会清理，使 Claude 显得健忘和重复，4 月 10 日修复；第三，4 月 16 日添加了减少冗长的 system prompt 指令，与其他 prompt 变更叠加后损害了编码质量，4 月 20 日回滚。由于三个变更影响不同时段的不同流量切片，聚合效果看起来像是广泛的、不一致的退化。Anthropic 表示将重置所有订阅者的用量限制作为补偿。详情

Anthropic Engineering: Scaling Managed Agents: Decoupling the brain from the hands

Anthropic 详细介绍了 Claude Managed Agents 的架构设计哲学，核心是将 agent 的"大脑"（Claude 和 harness）与"双手"（sandbox 和工具）以及"会话"（事件日志）解耦为独立接口。文章指出一个关键教训：最初将所有 agent 组件放在单个容器中导致了"宠物"（pet）问题，容器一旦失败会话就丢失，且因为容器持有用户数据，工程师无法直接进入调试。解决方案是借鉴操作系统的虚拟化思想，将 agent 组件抽象为 session（只追加的事件日志）、harness（调用 Claude 并路由工具的循环）和 sandbox（执行环境），每个都可以独立替换或失败而不影响其他部分。文章还提到一个有趣发现：Claude Sonnet 4.5 会在感知到 context 限制临近时提前结束任务（称为"context anxiety"），harness 中加入了 context resets 来解决，但 Opus 4.5 上这个行为消失了，resets 反而成了累赘。详情

Claude Blog: New in Claude Managed Agents: self-hosted sandboxes and MCP tunnels

Anthropic 为 Claude Managed Agents 推出两项重要更新：自托管 sandbox（公开测试）和 MCP 隧道（研究预览）。自托管 sandbox 允许 agent 在你控制的基础设施上执行工具，代码执行、敏感文件和数据始终留在企业安全边界内，而 agent 的编排循环和上下文管理仍由 Anthropic 基础设施处理。目前支持 Cloudflare（microVM 和轻量级隔离）、Daytona（完整可组合计算机，支持有状态长时间运行）、Modal（亚秒级启动，可扩展到数十万并发 sandbox，按需提供 CPU/GPU）和 Vercel（VM 安全性 + VPC 对等 + 毫秒级启动）四个提供商。MCP 隧道则允许 Managed Agents 连接私有网络内的 MCP 服务器，无需向公网暴露，只需部署一个轻量级网关发起单向出站连接，所有流量端到端加密。Amplitude、Clay 和 Rogo 等公司已在基于这些能力构建内部 agent 工具。详情

播客

AI & I by Every · Microsoft's Vision for an Internet Made for Agents With CTO Kevin Scott

核心收获：Microsoft CTO Kevin Scott 认为，AI 行业当前面临的最大挑战不是模型能力不足，而是存在严重的 capability overhang（能力过剩），即模型的推理能力已经超前于产品实际利用的水平，行业需要共同努力缩小这一差距。

Scott 从自身经历出发，强调对工艺有热情的人对工具和方法有强烈偏好是完全正常的，就像他既是程序员也是木工爱好者，过去四十年软件开发方式的重大变革这不是第一次。他指出 agent 要真正有用必须能替你采取行动、使用工具、修改系统并访问丰富的信息源，而这需要一个类似互联网的生态系统来支撑。作为 Microsoft 的 CTO，他正在推动公司内部所有系统都使用标准协议与 agent 通信，以避免陷入 Conway's law（康威定律，即系统架构反映组织架构）的陷阱。

他特别强调 agent 目前最大的短板是 记忆：现有 agent 基本是事务性的，你在一次任务中的上下文可能完成后就消失，下次从零开始，这严重限制了你能委派给 agent 的任务复杂度。他看好 MCP 等开放协议在 agentic web 中扮演类似 HTTP 在互联网中的角色，NL Web 则类似 HTML 的定位，简单、可组合的协议层将是让 agent 真正大规模可用的关键。详情
